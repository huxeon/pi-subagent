# pi-subagent

让 Pi 将任务交给多个子代理并行处理，收到结果后再汇总。子代理完成一轮工作后仍可继续交互，不必每次重新创建。

## 安装

需要 Pi 和 Node.js ≥ 22.19.0。目前已在 Pi 1.5.0、Linux 环境验证。

从本地项目目录安装，将路径替换为实际绝对路径：

```sh
pi install /absolute/path/pi-subagent
pi
```

如果只想单次试用：

```sh
pi -e /absolute/path/pi-subagent/index.ts
```

不要重复加载同一扩展。

## 使用

直接用自然语言向 Pi 安排工作：

> 启动名为 reviewer 的子代理审查代码，重点检查并发问题。你先继续完善文档，收到结果后再汇总。

继续与同一个子代理交互：

> 让 reviewer 接着检查测试是否完整。

安排多个子代理并行工作：

> 让 docs-reviewer 检查文档，test-reviewer 检查测试，最后汇总它们的意见。

也可以要求子代理先完成当前工作，再处理追加任务：

> 等 reviewer 完成当前审查后，再让它检查 README。

子代理默认使用父代理创建它时的模型和思考等级，也可以在安排任务时指定其他已配置的模型。名字不能重复；要继续已有子代理的工作，请使用原来的名字。

## 查看进度和结果

输入框上方显示当前子代理的状态：

```text
Subagents  reviewer · working | coder · idle
```

- `working`：正在工作，默认黄色。
- `idle`：当前空闲，默认绿色，仍可接收新任务。

颜色随 Pi 主题变化。**空闲不代表任务成功；工具调用旁的对号也只表示消息已被接收，不表示工作已完成。**

结果会自动返回父会话，并带上子代理名字，无需手动查询。父代理收到后会继续处理或汇总。较长的任务和结果可以展开查看。

## 使用前注意

- **不是沙箱。** 子代理共享工作目录和正常系统权限，可能同时修改同一文件，请明确划分任务范围。
- **会消耗模型额度。** 子代理并行工作以及父代理汇总结果都可能产生模型费用。
- 子代理不会自动获得父会话的历史，请在任务中提供必要背景。
- 使用自定义模型服务商时，请确保它在子代理中也可用；建议配置在 Pi 的用户级配置中。
- 退出 Pi、重载扩展，或创建、切换、派生父会话时，已有子代理会被关闭，不会随会话恢复。
- 暂不提供单独停止某个子代理的命令，也不支持自动重启。
