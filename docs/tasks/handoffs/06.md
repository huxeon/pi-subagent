## 最终 schema 与调用接口

工具名称 `subagent`，操作字段固定 **`operation`**，与已有内部联合一致。采用 provider 友好的单一 `Type.Object` + 字符串 enum，`additionalProperties: false`，只有 operation 在顶层 schema 必填；操作相关必填、互斥和字段范围在 execute 中严格再次检查（Pi 的 tool_call hook 可在 schema 校验后改参）。不使用 Type.Refine 或复杂 provider union。

| operation | 必填 | 可选 | 规则 |
| --- | --- | --- | --- |
| create | name, prompt | provider, model, thinking, cwd | 每项独立继承创建时父配置；cwd 相对当前父 cwd；不重复解析相对路径 |
| message | name, prompt | followUp | 默认 false；原样转交 manager |
| inspect | 无 | name, wait, timeout | 无 name 列表；wait 默认 false；wait=true 必须有 name |
| destroy | name | 无 | 停止并删除记录 |

- 其他操作的字段即使取 false 也拒绝，不默默忽略。未知字段拒绝。
- name 复用 `validateName` 的精确 Unicode/126 UTF-8 字节规则；prompt 非空白、保留原文。prompt/provider/model/cwd 拒绝 NUL、空白字符串。thinking 沿用当前 Pi 的 off/minimal/low/medium/high/xhigh/max。
- timeout **仅 wait=true 可给出**，单位秒，默认 **1800**。接受 **0.001 至 2147483.647**，精度为整毫秒；上限来自现有传输 API 的正 32 位整数毫秒限制。schema 有 minimum/multipleOf/maximum，execute 也检查有限值、范围、精度；边界转换 `Math.round(seconds * 1000)`。未扩大或改变传输层。
- 普通 inspect/message/create 的已有服务阶段超时照旧，不把等待 timeout 错用为创建/销毁总 deadline。
- Pi 1.5.0 的 StringEnum 在项目 typebox 的 Static 中推导为 unknown，使用 `Type.Unsafe<明确的字符串联合>(StringEnum(...))` 仅修正静态类型；实际 JSON schema 和运行时校验没有绕过。

导出接口：

```ts
subagentSchema;
type SubagentInput;
validateToolInput(value: unknown): SubagentOperation;
createSubagentTool(current, config): ToolDefinition;
registerSubagentTool(pi, lifecycle): void;
// current 是窄 Service getter；config(ctx) 在每次 create 调用时取快照。
```

`src/index.ts` 持有 `const lifecycle = registerParentLifecycle(pi)` 并传给 `registerSubagentTool`。07 应复用这一个 lifecycle 给工具和 UI，**不可再次注册或创建另一 manager**。工具 execute 不读 ctx.ui/hasUI，不依赖 TUI，print/json/rpc 可同样调用。

## 结果、模型 content 与渲染 details

所有正常执行分支，包括部分更新/错误，返回：

```ts
{
  content: [{ type: "text", text: "..." }],
  details: {
    version: 1,
    phase: "running" | "done" | "error" | "cancelled" | "timeout",
    config?: { cwd, provider, model, thinking },
    data?: /* manager 原结果或下面所列快照 */,
    error?: { code, message }
  },
  isError: boolean
}
```

- create data：`{name, config: 实际有效配置, invoked:true}`；partial config 为当前解析配置，final 接受 manager 返回的合法 thinking clamp。独立保留实际 cwd。
- message data：`{invoked:true}`。**只代表 Pi 输入 API 调用已发起**，模型 content 明确不保证接受、排队、落盘或完成；卡片仍显示 `✓ Delivered`。
- inspect list data：`{name,status:Availability}[]`；有名非等待强制只保留 `{state}`，即使适配器错误地附 reply 也剥除。等待 data 保留 `{state:"idle",reply:{text,stopReason,errorMessage?}|null}`，不丢弃空 aborted/error。
- destroy data：`{destroyed:true}`。
- 请求失败/超时/主动取消均 `isError:true`，因此不会在 Pi 执行器中被当成成功；主动取消的**显示**是中性文本、无叉号。查询成功但最近 assistant error/aborted 时工具查询本身仍成功，data/content/卡片保留该回复的结果信息，不将 idle 当任务成功。
- content 是英文操作/结果/确认语义的 JSON 元信息；等待且有回复时，把 stopReason/errorMessage 放在元信息前部，回复 text 在其后以原文输出。无 outputSchema/structuredContent，不承诺 content 是可解析的完整 JSON。
- 模型输出最多 50 KiB / 2000 行，预留说明空间（正文 50944 bytes / 1995 行）；UTF-8 边界安全截取前缀，包含截断提示。完整返回回复保留在该**父工具结果 details** 中，展开历史卡片可读；不另存回复文件、不复制子 session 历史作管理状态。传输原有 1 MiB 单帧限制不变，超大响应仍明确请求失败，不承诺突破此限制获取全部历史。
- details 没有 PID、连接、等待记录、权威管理状态；不用于恢复子进程或刷新 UI。卡片重载只需父会话已存的 args/content/details，子代理离线或已 destroy 仍可重建原结果。

## 取消与安全边界

- execute 收到的 signal 原样传给 create/message/inspect/list/destroy；预取消不分发。列表服务原本隔离单项失败，工具在 list 后补检查用户 signal，避免取消被包装为普通列表成功。
- inspect 复用原 socket cancel；不调用 Pi abort、不停止子进程、不清空 steer/follow-up，不重写状态。真实 manager/socket 测试确认取消/超时后等待记录为零，另一次状态查询仍 working。
- `ParentManager.destroy(name, options = {})` 是向后兼容的新签名。进入 mutation、停止前、停止后、socket 清理后及实际删除前检查 signal。已发起的 graceful stop 必须等它安全结束，不以取消为由中途放弃清理；若期间取消，停止结束后保留 session、返回 ABORTED，不宣称删除完成。删除一旦开始不提供事务回滚；取消卡片提示部分副作用可能已发生。这个行为不扩展“inspect 取消不停止子”的特定保证到 destroy/create。
- create 原本失败回滚不变；cleanup incomplete 不因用户 signal 已 abort 就被掩盖为普通取消。

## 卡片渲染

使用 Pi 默认 shell，不接管终端、不创建后台资源。`renderCall` / `renderResult` 共享**行内** `CardState.hasResult`；Pi 先构造两个 slot 再 render，call slot 延迟读取该标记，有 result 时隐藏初始卡片，由 result slot 展示完整历史卡片，避免标题/状态重复。真实 `ToolExecutionComponent` 测试覆盖该组合、partial→final、重载和展开。

- 英文标题/状态/提示；prompt 和回复不翻译。显示前剥离终端控制序列，原始数据不改。
- create 摘要、实际 cwd 保留，完成仅替换 Creating... 为 `✓ Created · provider/model:thinking`；展开完整 prompt/有效配置。
- message 默认无 prompt/steer 标签，仅显式 true 显示 follow-up，统一 `✓ Delivered`。
- inspect 无等待仅状态；等待 `Waiting for completion...`，完成后标题/idle/回复分空行，无 `✓ idle`。错误 assistant 用叉号与错误信息，中止 assistant 中性说明，均不跳过原回复。
- destroy `Destroying...` → `✓ Destroyed · session data deleted`。
- 请求错误/超时用 ✗；取消等待 `Wait cancelled. Subagent continues running.` 无叉；断线明确 status unknown，不声称完成。其他取消提示可能已有副作用。
- prompt 默认最多 3 个**折行后**内容行；普通结果/列表/错误 8 行；Markdown 回复 10 行；超限显示注入 keyHint 的英文展开提示；展开不裁内容。Text/Markdown + visibleWidth/truncateToWidth 处理中文/emoji/长行/窄宽度。大数组拼接不使用无限 spread，避免极窄终端展开长回复时触发调用栈溢出。
- Pi 自身产生的校验/阻止/异常结果可能 details 为 `{}`，必须验证 version/phase 才使用自定义结果；其余走 content + context.isError 的失败展示，不能把 `{}` 当成功。宿主标准 `Operation aborted` 特判中性取消。
