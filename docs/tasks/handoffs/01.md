## 工具接口及排除验证

`subagent` 提供 `spawn`、`send` 两个子命令，通过 `action` 参数选择：

```ts
subagent({ action: "spawn", name: "reviewer", message: "检查代码" });
subagent({ action: "send", name: "reviewer", message: "重点检查并发", mode: "steer" });
```

子进程启动参数 **`--exclude-tools subagent`** 按注册名排除整个工具，使两个子命令都不可调用。spawn 接受 provider/model/thinking，send 接受 mode；详细规则见 `docs/spec.md`。

实现核对依据（均相对于当前安装的 Pi 包）：

- `dist/cli/args.js`：把 `--exclude-tools` 解析为逗号分隔的排除项。
- `dist/core/mcp-servers.js`：`createToolNameMatcher()` 只匹配精确名称或带 `*` 的全名模式。
- `dist/core/agent-session.js`：`_isAllowedTool(name)` / `_refreshToolRegistry()` 按 `definition.name` 过滤工具注册表；`_getCallableTools()` 决定其他工具经 `ctx.executeTool()` 可访问哪些工具。

`tests/tool-exclusion.test.ts` 在三种 exposure（direct、codemode、deferred）下分别检查启用与排除状态，共 **6 个场景**：

| 场景 | 注册/可调用状态 | 实际嵌套调用 |
| --- | --- | --- |
| 排除 `subagent` | 工具不存在，重新激活也无效 | 两个 action 均 `Tool subagent not found`，执行计数为 0 |
| 不排除 `subagent` | 工具已注册且可调用 | spawn/send 两个 action 均真实执行计数桩 |

这些测试同时检查注册表、初始模型声明、可调用工具集合、尝试重新激活以及通过另一个工具真实执行 `ctx.executeTool()` 的结果，不只检查模型声明。codemode/deferred 工具即使初始没有模型声明，也能通过嵌套路径访问。

- `onEvent(listener)` 返回取消订阅函数；listener 是同步 void 边界，后续异步取结果/投递需自行捕获错误。
- `getLastAssistantText()` 返回 `Promise<string | null>`；回报边界是 `agent_settled`，不是 `agent_end`。

## 实际共享接口及纯函数

`src/types.ts`：

- `SubagentName = string`：同一父会话的精确名称键，不做大小写或路径归一化；唯一性由任务 03 管理器负责。
- `SpawnInput` / `SendInput` / `SubagentInput`：以 **action** 判别。provider/model 的成组约束在运行时校验；send.mode 输入可省略。
- `ParsedSubagentInput`：send 分支的 mode 已补齐；spawn 不在解析阶段继承父配置。
- `ParentConfigSnapshot`：只保存调用时的 cwd、model.provider/id、thinkingLevel 数据；model/字段允许缺失，解析时仅在需要继承时要求相应父值。
- `ResolvedChildConfig`：必需的 cwd/provider/model/thinking，均为解析时复制的值，不保留父上下文引用。
- `PromptDisposition` / `SubmissionResult`：接收状态为官方返回值，结果形状 `{ name, disposition }`。
- `RpcAdapter`：从官方 RpcClient Pick 出 start/getState/prompt/onEvent/getLastAssistantText/stop；`RpcAdapterFactory(config)` 返回该接口，供管理器注入依赖。任务 02 才实现创建及包装。
- `SubagentReport = { name, text: string | null }`；`ReportReceiver(report)` 支持 void 或 Promise<void>。任务 04/05 才落实 pi.sendMessage 投递以及过期运行时保护。

`src/config.ts`：

- `SUBAGENT_TOOL_NAME = "subagent"` 和 `THINKING_LEVELS` 可供后续启动参数/schema 复用。
- `parseSubagentInput(unknown)`：校验 action、必要文本、spawn 配置成组和 thinking 枚举、send.mode；mode 默认 steer；失败抛 Error。
- `resolveChildConfig(SpawnInput, ParentConfigSnapshot)`：重新校验 spawn，再独立继承模型对/thinking；全部显式提供时根本不读取父 model/thinking；所需父值缺失时报错；cwd 来自调用时快照。
- 名字/消息只要求字符串且非空、非纯空白，保留原字符串；不增加长度、路径编码或大小写规则。provider/model 也拒绝提供的空字符串。未实现重名防护、I/O、模型存在性查询或 RPC 调用。
