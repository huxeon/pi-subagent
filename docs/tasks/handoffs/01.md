## 用户已确认的投递语义（原阻塞已解除）

`pi.sendUserMessage(...)` 的扩展签名返回 void，AgentSession 的 async Promise 被内部 catch 后 emitError。即使 `await` 或 `try/catch` 包住扩展调用，也无法确认输入接受/排队，更不能确认初始会话已写出。

用户已接受确认仅代表 **调用已发起**，不要求可靠投递。任务 04 的桥在调用后即可确认；任务 06 保留 `✓ Delivered` 展示，但不得把它解释为接受、排队、落盘或任务完成的保证。不增加逐消息接受确认、重投、消息记账或 metadata，不依赖内部 AgentSession API。

**create 的独立约束仍保留**：spec 12.1 要求创建成功时已有足以恢复的会话，任务 05 仍需检查初始有效会话落盘，不能拿桥 ready 或 void API 返回代替。用户本次确认没有取消此要求；这不等于为每条 message 实现可靠投递。具体检查和失败处理由任务 05 实现、测试，不在本任务提前编码。

单 `session.jsonl` 的正常恢复已验证成立，无需扩展持久化格式。后续任务可按顺序继续，不再等待投递语义确认。
