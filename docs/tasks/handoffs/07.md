## 文件和接口

- `src/ui-refresh.ts`：`UiEntry`、`UiClock`、`UiSource`、`UiRefresh`。可注入间隔时钟；`start()` 幂等、立即首次查询，然后每 1000ms 查询；`settled()` 只等待已有轮次；`subscribe()` 返回解绑函数；`stop()` 幂等取消/清理。
- `src/ui-components.ts`：纯 `renderWidget(entries,width,theme)` 和交互 `SubagentPicker`，用 Pi 的 SelectList 渲染及注入的 KeybindingsManager 处理键盘。
- `src/parent-ui.ts`：`registerParentUi(pi,lifecycle,clock?)`、`attachTerminal(tui,target,run?)`。
- `src/index.ts`：仍只注册一次父生命周期，同一返回对象交给工具和 UI；子角色提前 return，不注册人工命令。
- `src/parent-lifecycle.ts`：返回值新增 `onStopping(cleanup: () => void): void`。session_shutdown 最先同步调用 session UI cleanup，然后在 finally 调用原 manager.shutdown(reason)，即 UI 清理异常也不跳过原进程清理。没有改变 reload/quit/new/resume/fork 的子代理停止边界。
- `tests/parent-ui.test.ts`、`tests/parent-ui-command.test.ts`：新增 9 组测试；基础和子桥入口测试适配父命令注册并断言子角色无命令。

## 刷新器与连接所有权

1. **只在父 `session_start` 且 `ctx.mode === "tui"` 时**建立一个 UiRefresh。不能用 hasUI 代替 mode，因为 RPC 也 hasUI=true。工厂不启动资源；RPC/json/print 不访问 UI、不启动轮询/终端接管。命令虽在父工厂注册，但非 TUI handler 直接返回。
2. 刷新调用现有 `manager.list({timeoutMs:600,signal})`。manager 每轮重新扫描关系目录，逐名称并行 socket inspect，单项失败转 unavailable；600ms deadline 包括连接、identity 和 inspect，不为坏条目无限等待，不串行阻塞其他条目查询。整批在所有并行查询完成/超时后发布同一快照。
3. widget 和已打开 picker 订阅**同一个快照对象**。列表打开不启动刷新、不额外查询，只通过 settled 等待已进行的刷新。定时 tick 发现上一轮未完成直接复用 Promise，不叠加。
4. 不额外开一套 UI socket 或平行 manager：连接仍归同一 ParentManager 所有，可与工具并发请求。UI stop 取消本 UI 查询，随后既有 manager.shutdown 关闭共享连接；不能为关闭 picker 而关闭仍被工具使用的连接。UI 无权停止子代理。刷新取消/失败不改变工作状态或 wait=true 等待记录。
5. 创建、destroy、recover 的关系变化由下一轮扫描完整替换快照。全局扫描错误不保留旧 available 状态：已有条目降为 unavailable，并记录内存错误；打开命令时报告错误。没有用历史工具结果、磁盘状态或 socket 文件存在来冒充实时状态。
6. 关闭后丢弃快照、清 listeners、清 interval、abort 查询；迟到 Promise 完成不会更新旧 widget/上下文。纯渲染不做 I/O。

## widget 与 picker

- widget placement 固定 `belowEditor`；零条目清除 widget。最多展示 5 条，按实际宽度减小条数，预留 `+N more`；名称通过 `truncateToWidth` 截断并保留状态。极窄终端降级为总数提示（最终仍按宽度裁剪），不承诺在 1–7 列同时容纳名称和状态。
- 全部固定提示为英文，名称原文/精确身份不变；显示前剥离终端控制符，不修改底层名称。使用主题 accent/dim/muted/warning/success 和 visibleWidth/truncateToWidth，支持中文/emoji/长名。
- picker 使用 SelectList 的有界滚动渲染（8 条）；自定义 primary 截断为状态预留宽度，避免长中文名挤掉状态。键盘由 **注入的** keys 匹配 up/down、pageUp/pageDown、confirm/cancel，并生成配置提示；不依赖 SelectList 内部全局 keybindings 或鼠标。
- 当前选择按精确 name 保留，重排和状态变化不会跳动。选中条目消失时保留一个 disabled unavailable tombstone，直到用户显式导航；不会把同一索引的新邻项当作原选择。不可用条目确认不关闭/进入。取消关闭，无副作用。
- 确认后先关闭 picker，再调用原 manager.inspect(name,false,{timeoutMs:600,signal}) 直接复核；失败报告错误，不根据陈旧 UI 快照进入。该一次性复核不是第二个刷新器，也不替代工具 inspect。

## 终端接管与清理

- target 复用 `getSubagentPaths` 和 `tmuxSessionName(runDir)`，传 `=pi-subagent-<hash>` 精确 session target；不使用用户名称拼 shell。
- 已在 tmux：`pi.exec("tmux",["switch-client","-t",target],{timeout:5000,signal})`，检查 code/killed，错误通知；不暂停父 TUI。用户用 tmux session 切换返回原父 session。
- 不在 tmux：通过 `ctx.ui.custom` 获取宿主 TUI，`attachTerminal` 在 try 中 stop，再 `spawnSync("tmux",["attach-session","-t",target],{stdio:"inherit"})`；detach、spawn error、非零退出或异常都在 finally start + requestRender(true)。错误值从 custom 返回后再通知，避免同步 done 后异常被宿主当作已完成交互吞掉。
- 同步 attach 沿用宿主 interactive-shell 示例：终端交给 tmux 时父 JS 事件循环暂停，避免父 timer/模型更新写坏终端；detach 后继续刷新。不是新增子进程生命周期管理，也不会主动停止目标 session。
- lifecycle.onStopping 在原 manager 停止前清掉 UI；abort signal 关闭打开的 picker，dispose 解绑快照和 abort listener。退出/切换/reload 共用清理；关闭 picker 本身不停止常驻刷新。reload 的子代理存活规则完全沿用任务 05。
