## 下一任务使用的 API

```ts
const lifecycle = registerParentLifecycle(pi); // 每个父 runtime 只调用一次
// session_start 后：
const manager = lifecycle.current();
const config = parentConfig(pi, ctx); // 创建时调用，不能缓存 startup 时的旧配置
const created = await manager.create(
  { operation: "create", name: "reviewer", prompt: "Review", cwd: "../project" },
  config,
  { signal },
);
// created: { name, config: 实际生效配置, invoked: true }
await manager.message("reviewer", "Also check cancellation", false, { signal });
await manager.inspect("reviewer", false, { signal });
await manager.inspect("reviewer", true, { signal, timeoutMs: 1_800_000 });
await manager.list({ timeoutMs: 1000, signal });
await manager.destroy("reviewer");
```

- 入口目前只调用 registerParentLifecycle；06 应保留其返回值并让工具/UI 共用 `.current()`，**不要第二次注册 lifecycle 或创建平行 manager**。子角色仍提前 return。
- `ParentManager(options)` 不依赖 Pi context/UI；options 含 agentDir、parentSessionId、driver，支持注入 connect/transport 与 readyTimeoutMs/persistenceTimeoutMs/pollMs。默认 ready/初始落盘各 30 秒，轮询 50ms；只有操作期间轮询，没有长期刷新器。
- `ProcessDriver.start(paths, config?) / isRunning(paths) / stop(paths)`；config 缺省是恢复，严禁重新继承父配置。start resolve 表示 tmux 启动命令完成，不表示桥或 session 已就绪。
- `message` 默认 30 秒，非等待 inspect 默认 1 秒，等待 inspect 默认 **1,800,000 毫秒**。RequestOptions.timeoutMs 均为正的 32 位整数毫秒；06 工具的秒数须在边界转换。deadline 包含连接/身份查询和请求；signal 同时用于连接和请求。各连接尝试独立拥有调用者取消，复用已连上的连接支持并发等待。TIMEOUT/ABORTED 沿用 SocketTransportError，不停止 Pi、不重投消息；其他请求失败关闭坏连接，下一次操作可重连（不会自动重启进程）。
- create 的 options.timeoutMs 只控制初始 message RPC；启动/落盘有上述独立阶段上限，signal 可取消整个创建。成功只要求初始可恢复会话，不等待 assistant/idle。
- inspect 返回既有 InspectResult；message 返回 `{ invoked: true }`，仍然**仅代表调用发起**。list 每次扫描+即时查询，结果是 `{name,status:Availability}[]`，单个失败表达为 connection-error，不用旧状态冒充在线。
- recover 返回 `{name,connected,error?}[]`；单个失败不拒绝整批（扫描根目录本身不安全等全局错误除外）。lifecycle.recovery() 提供最后一批结果；session_start 完成所有条目后将失败汇总 throw，由 Pi 扩展错误路径报告，不创建人工 UI，不妨碍已恢复条目使用。
- shutdown(reason) 幂等共享 Promise；关闭后的实例不可复用，新 runtime 建新实例。destroy 同名并发串行、重复销毁缺失目录成功；其他操作也用每名称内存 mutation 锁保护 create/recover/destroy，不是消息队列。

## 创建、会话有效性与配置

1. 复用精确 name 编码及独占 mkdir；同名 EEXIST 不进入失败清理，不覆盖任何已有目录。不同父会话隔离。创建 cwd 相对父创建时当前 cwd 词法解析，检查实际目录；provider/model/thinking/cwd 分别独立继承。父之后改变配置不影响子。
2. 不预建 JSONL。独占拥有目录之后先检查旧进程、用既有安全 helper 检查残留端点；可连接 socket 不删除。启动成功后等桥 identity，再发初始 prompt。
3. `readSessionRecord` 只读 lstat/readFile/JSON.parse + Pi 公共 buildSessionContext，不用可能修复/写文件的 SessionManager.open。要求普通非链接文件、当前 Pi 原生版本 3 header/id/绝对 cwd、无重复/断裂父节点的 entry tree、model/provider、thinking entry 与有效 thinking、当前恢复上下文中存在 user 或 assistant。拒绝空文件、setup-only、坏 JSON、缺配置/坏树；创建期短暂不完整读取会重试直到独立落盘超时，不伪造 entry、不落额外状态。
4. 配置根据**磁盘当前分支**的 Pi projection 解析，而不是全历史最后一条 model。creation 比较桥实际配置和初始记录；cwd/provider/model 不允许悄悄 fallback。Pi 合法的 thinking clamp 接受并作为实际 config 返回，磁盘必须匹配该实际值。
5. ready 和 invoked 都不是落盘证据；只有通过上述文件检查才返回 created。此检查不是逐消息接受/投递协议，也不是 fsync/断电事务保证。当前服务针对本扩展创建的 v3 原生记录，不实现旧版会话迁移或坏尾修复。

## 控制桥只读 identity

既有同一 socket，`request("identity", {})` 返回：

```ts
{ runDir, sessionFile: string | null, pid, cwd,
  provider: string | null, model: string | null, thinking: string }
```

从实际 ctx/sessionManager/pi.getThinkingLevel/process.pid 即时读取；不读/写 session，不引发 prompt。父连接必须匹配原样 runDir、sessionFile 以及有效 PID，避免把其他监听者当作本子会话。新启动恢复还比较磁盘原配置，发现模型 fallback 报错并停止本次新进程，保留原记录。identity 是运行时观察，不持久化 PID，也不是新增业务 ID/可靠投递回执；旧版无 identity 的桥不能无条件当成新版就绪桥，父会报告错误而不覆盖其端点。

## tmux、进程定位与正常停止

- session 名固定 `pi-subagent-` + 既有 hashRunDirectory(runDir) 的 32 位 hex；使用 tmux 精确 `=sessionName` target，不用用户可控 name 拼 shell。
- execFile 调 tmux，new-session 使用多个 shell-command argv（env + pi），不用 sh -c/字符串拼接。首次 `--session 原绝对路径 -e 同一个包根 index.ts --provider ... --model ... --thinking ...`，tmux -c 传创建 cwd。恢复**只有** `--session 原路径 -e 同入口`，初始 tmux cwd 使用 agentDir，Pi 自己从 header 恢复 cwd，不作为 override。
- 明确传入 `PI_SUBAGENT_RUN_DIR`、`PI_SUBAGENT_SESSION_FILE`、固定 `PI_CODING_AGENT_DIR`；其他当前父环境通过 tmux `-e` 传入，避免长存 tmux server 的 XDG/PATH/认证环境过时。额外 SESSION_FILE env 是纯运行时进程定位信息，不是磁盘记录。正常发现资源不筛选，不添加 approve/offline/隔离开关。相同 package entry 的发现与 -e 去重沿用 01 验证，不另加桥入口或进程级永久 sentinel。
- 检查 session 的 live tmux 环境 RUN_DIR 标记，拒绝同名 foreign session。Linux /proc 扫描当前 UID 的候选进程，要求运行目录+会话路径两个初始 env 匹配；启动期可识别保留 `--session` argv 的进程，运行期识别 Pi 原生 `process.title='pi'`（会覆盖 /proc cmdline）。使用 /proc stat starttime 作内存身份，再次确认后才 SIGTERM。没有依赖 pane_pid 永远是 Pi，也能发现 tmux 消失但 Pi 尚存的孤儿进程。
- 同时核对 live pane PID 是否在已确认进程中；launcher 尚未 exec 时有限等待。无法确认的 live pane、不可读取候选身份、foreign session 均 fail closed，不直接 kill-session。
- 正常停止向确认的 Pi 发 SIGTERM，等待进程不再存在/成为 zombie，才删除残余 tmux session，然后 manager 清残留 socket。正常 Pi 异步 shutdown 行为沿用 01 实测，不用 tmux session 消失替代 Pi 退出证明。
- 停止上限默认 10 秒，tmux 单命令上限 10 秒。不自动 SIGKILL 降级：停止超时/无法确认归属明确报错，保留资源和记录，不声称完成正常清理。start 的非确定性超时若无法确认资源归属，同样保守保留并报告 cleanup incomplete。
- 当前生产 driver **只支持 Linux /proc + 当前 Pi 的 `pi` 标题**；其他 OS 明确报错，重品牌/改标题包装器需要另行验证。未声称跨平台支持或抵御恶意同 UID 竞态；非 pidfd 的身份复核仍不是原子 signal-by-identity。

## 恢复与资源清理

- session_start 固定 agentDir/session ID 后扫描既有 canonical 目录，先连接 identity；连得上则保留其工作现场，不发 prompt、不改配置。
- 仅 ENOENT/ECONNREFUSED/连接关闭才考虑启动路径；权限、身份错误等不当成“已死”。旧进程或 live tmux 尚在时只有限等待重新连桥，超时报告、不启动第二份。确认无旧进程之后，验证原 JSONL/原 cwd，安全清残留 socket，start(paths) 加载历史。空/坏记录保留并报告，不能擅自把它当新建或删除。
- 新进程恢复失败会尝试正常 stop；保留整个原运行目录/会话，单项错误隔离。不会重发旧 prompt、覆盖配置、恢复等待请求或自动续跑任务。
- 父 reload 取消父等待/连接，但不停止已建立的子代理。quit/new/resume/fork 停止所有当前父目录中可安全扫描的子代理，并保留记录；单项停止失败不会阻止其他停止，最终汇总错误。进行中的失败创建仍回滚其新建资源，不将半创建关系冒充成功协作者。
- create 失败只清理独占 mkdir 后自己创建的资源；若启动不确定且观察到旧/不明进程，不误停，报告不完整清理并保留。已 launch 的本次进程正常停后，才清 socket 与运行目录。停止失败绝不删除仍活进程的历史。
- destroy 对活动/已停止协作者均 stop、等退出、清 socket、重新核对 subagents/parent/run 非链接目录后递归删除整个 runDir。缺失目录重复 destroy 不触碰其他资源；拒绝目录被替换为 symlink。不同父会话数据保留。
- socket 清理直接复用 03 的当前 UID/socket 类型、拒绝 live endpoint、两次探活和 inode 检查；不删普通文件/链接/其他监听者。共享 0700 runtimeDir 及父目录不删，仅删该 socket/runDir。
