## 实际公开接口与调用示例

注册名始终为 **`subagent`**，默认 direct/active；不拆分 spawn/send 工具，不新增命名空间或别名。子进程沿用 `--exclude-tools subagent`，整个工具及两个 action 一起排除。

模型工具调用示例：

```ts
subagent({ action: "spawn", name: "reviewer", message: "检查代码" });

// thinking 可独立指定，模型对从调用时父 ctx 继承。
subagent({ action: "spawn", name: "reviewer-high", message: "检查并发问题", thinking: "high" });

// 显式模型对 + 独立 thinking；provider/model 不允许只传一个。
subagent({
  action: "spawn", name: "specialist", message: "复核实现",
  provider: "openai", model: "gpt-4o-mini", thinking: "off",
});

subagent({ action: "send", name: "reviewer", message: "继续检查测试" }); // 默认 steer
subagent({ action: "send", name: "reviewer", message: "结束后检查文档", mode: "followUp" });
```

成功结果示例：

```ts
{
  content: [{ type: "text", text: '{"name":"reviewer","disposition":"started"}' }],
  details: { name: "reviewer", disposition: "started" },
}
```

- disposition 原样使用 SDK 的 `started | queued | handled`，不是任务完成状态。仅等待 RPC 接收确认，不等 settled、不提前取文本。
- 工具 description 明确接收确认不代表完成、settled 后异步回报、子代理保持运行可继续 send，以及 handled 可能没有回报。
- 参数、未知名字、重名、缺失父配置、RPC/压缩拒绝等均抛错；RPC 原错误对象和文本不被包装、吞掉或重试。
- 名字/消息不 trim、不编码、不折叠大小写；JSON 结果仅按标准 JSON 转义显示，管理器键仍是原始字符串。

### Schema 与校验职责

`src/tools.ts` 导出 `subagentParameters` 和 `registerSubagentTool(pi, manager)`。

- 顶层为普通 object；必需字段只有 action/name/message。
- action 的普通 enum 为 spawn/send；mode 为 steer/followUp，schema 标示默认 steer，运行时解析器也真实补齐默认值。
- thinking 普通 enum 复用 `THINKING_LEVELS`，包括 off/minimal/low/medium/high/xhigh/max。
- name/message/provider/model 的字符串 schema 用 minLength + `\\S` pattern 排除空白，不修改文本。
- provider/model/thinking/mode 都是可选属性，description 标明适用 action 及模型对规则。**provider/model 成组约束在 execute 的已有 `parseSubagentInput()` 中强制校验，不使用复杂的顶层 union/条件 schema。**thinking 单独提供不受模型对约束影响。
- execute 再校验一次也覆盖 Pi tool_call hook 在 schema 校验后修改输入的路径。

### 调用时配置与最小注入边界

```ts
import extension from "./index.ts";

// Pi 的正常入口；只注册，不启动子进程。
extension(pi);

// 受控测试/宿主可选地注入已有 RpcAdapterFactory，不增加管理器工厂框架。
extension(pi, { createClient });
```

- 每次 extension 调用都在函数内部创建新 `SubagentManager`，没有模块级管理器/子代理集合。
- factory 只构造无后台资源的管理器、注册一个工具和一个 shutdown handler。生产默认 RpcAdapter 仍仅在 spawn 中创建/启动。
- spawn 从当次 execute 的 `ctx.cwd`、`ctx.model.provider/id`、`ctx.thinkingLevel` 复制普通快照，交给管理器解析继承；不缓存 factory/session_start 配置，不保留 ctx/model 对象。
- send 只传已解析的输入，不读取父配置或 cwd，不重新配置子代理。
- `registerSubagentTool` 的管理器边界只需要 spawn/send；生产入口传入真实管理器，测试可用 prototype spy 验证确切委托参数。

### 回报和关闭接线

父投递使用立即委托：

```ts
sendMessage: (message, delivery) => pi.sendMessage(message, delivery)
```

不解绑定、不在注入函数内延迟排队。沿用任务 04 的完整 content：`Subagent: <name>\n\n<text>`；null 明确显示 `(No assistant text available.)`。

实际接线测试断言：

```ts
{
  customType: "subagent.report",
  content: /* 原始名字 + 最后 assistant 文本 */,
  display: true,
}
// 第二参数固定：
{ deliverAs: "steer", triggerTurn: true }
```

send.mode 为 followUp 时也不改变回报选项。`session_shutdown` handler 无 reason 过滤，统一 await 当前管理器 shutdown；不使用 session_start 重置旧实例。旧 listener/在途文本读取的关闭保护继续由已有管理器负责。

## 测试设施、实际命令与结果

`tests/extension.test.ts` 的本地 fake 仅实现 registerTool/on/sendMessage，并通过 Proxy 拒绝多余 API 访问；ctx 只提供实际需要的配置字段。复用已有 `FakeRpcClient`，用 deferred Promise 控制确认、取文本和停止，不构造通用框架或模型网络响应。

覆盖：

- 根导出可直接调用；单工具注册/schema/enum/default/说明文本。
- 包含生产默认分支的 factory 不调用进程启动、计时器、watcher 或注入的 client factory。
- spawn/send 确切委托参数、mode 默认/显式值、调用时父快照；修改父配置后下一次 spawn 读取新值。
- 真实工具→管理器→fake RPC 的模型对/thinking 四组合、独立 thinking、完全显式配置及 cwd。
- 部分模型对、非法必要文本/枚举/action、缺失所需父配置、未知名字、重名和压缩 RPC 错误。
- started/queued/handled：spawn/send 都等各自确认但不等 settled，不取结果；所有确认结果都保留 name/disposition。
- 生产 pi.sendMessage 包装准确、this 绑定不丢失、内容/null 和选项精确一致。
- quit/reload/new/resume/fork 每个 reason 都等待清理、立即拒绝新请求、移除监听、stop 一次；新实例不能 send 旧名字、可以重新 spawn 同名；旧读取/旧回调不能投递，只有新实例回报到新 API。
- 实际 Pi/jiti 通过绝对根入口加载成功，注册工具及 shutdown handler；只加载 factory，不启动会话或发送 prompt。
- SDK 排除测试真的执行生产 factory。启用时嵌套 spawn/send 经 schema→真实管理器→fake RPC 成功；thinking 单独提供可经过 SDK 校验，provider/model 部分提供得到 Pi 的 `isError: true` 结果。
- 排除时生产工具从注册表/模型声明/可调用集合消失，尝试激活无效；另一个工具嵌套调用两个 action 都得到 `Tool subagent not found`，client factory 和 prompt 都没有执行。
