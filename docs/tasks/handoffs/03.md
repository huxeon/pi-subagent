## 实际管理器接口

```ts
import { SubagentManager } from "./src/manager.ts";

const manager = new SubagentManager({
  createClient, // 可省略，默认使用生产 createRpcAdapter
  onEvent(child, event) {
    // 必需的同步事件接收边界；child 包含 name/config/client。
    // 任务 04 在此实现 settled 处理，并捕获自行启动的异步操作错误。
  },
});

await manager.spawn(spawnInput, parentConfigSnapshot); // Promise<{ name, disposition }>
await manager.send(sendInput);                        // Promise<{ name, disposition }>
```

- `SubagentManagerOptions.onEvent` 必需，没有默认丢弃事件的 no-op，也没有临时回报逻辑。
- `createClient?: RpcAdapterFactory` 是唯一客户端创建注入点，沿用任务 02 的生产工厂和启动就绪检查。
- `SubagentHandle` 是只读资源视图：`name`、已解析的 `config`、`client: RpcAdapter`。事件消费者能访问正确子代理的 `getLastAssistantText()`，不必按名字重新查找客户端。
- `SubagentEventListener(child, event)` 使用官方 `JsonAgentSessionEvent`。全部事件原样同步转发，不筛选 settled、不取文本、不模拟父消息。
- spawn/send 重新使用已有解析器校验参数，并拒绝传错 action。成功返回接收结果；失败抛出 Error/RPC 原错误，交给任务 05 转成工具错误。
- 没有公开 list/status/wait/stop 等管理工具；每个父运行时应创建一个新管理器。

## 记录生命周期及关键约束

管理器私有 `records: Map<string, Reservation>` 同时保存名字预留与成功子代理，不使用模块全局集合。

1. **校验/解析**：同步解析输入、检查精确重名、复制 cwd/provider/model/thinking。复制后的消息/名字/配置在任何 await 之前确定，异步启动后不再读原始输入或父对象。
2. **starting**：在调用同步 factory 之前就设置记录，连 factory 重入也不能重复创建同名子代理。创建的 child 在 await start 之前立即保存在记录上。
3. **监听与初始提交**：等待适配器 start（其内部确认 getState），安装 listener，再调用 `prompt(message)`。此时尚未返回 spawn 也能转发快速完成事件。
4. **ready**：初始 prompt 接收确认后立即转为 ready 并返回结果；不等待 settled。保留监听及进程，后续 `send` 调用 `prompt(message, undefined, mode)`。
5. **失败回滚**：factory/start/订阅/初始 prompt 出错，先标记 failed、尝试取消订阅，再尝试 stop，最后按记录对象身份比较释放名字。清理期间仍持有名字，避免旧清理干扰新记录。取消订阅或 stop 自身失败不掩盖原错误，也不阻止另一步清理和名字释放。

**启动中的 send 行为已明确**：只要记录尚未 ready（包括等待初始 prompt 接收确认），立即抛出 `Subagent "…" is not ready`，不等待、不隐式排队。未知名字抛出 `Unknown subagent "…"`；重名抛出 `Subagent "…" already exists`。

send 提交失败不停止/删除既有子代理，不重试；SDK 既有失败语义保持不变。同一 ready 子代理的多个 send 可以并发，各自等待自己的接收确认。

listener 转发前检查当前 Map 项仍为原记录且不是 failed，避免回滚后迟到的旧 listener 将事件归给重用名字的新子代理。**这仅是事件入站身份保护，不是异步回报的关闭/过期保护。**

## 未验证项及任务 04 注意事项

本任务未启动管理器的真实模型任务，未消费 API 配额，也未操作用户现有会话或配置。默认测试仍会运行任务 02 已有的受控 SDK 子进程 stop 测试；本次没有重跑可选真实 CLI 探针。生产扩展接线/默认资源加载/排除全链路仍留给任务 05–06。

**任务 04 需要实现和验证，当前没有宣称完成：**

1. 仅 settled 取最后 assistant 文本并回报；agent_end 不回报。回报格式/null/父投递选项和异步错误捕获。
2. 管理器关闭标志、拒绝新 spawn/send、先阻止回报、并行停止、监听清理、批量记录清理、停止失败隔离和幂等 shutdown。
3. **不要等 start/初始 prompt 完成才开始 stop。** 当前 starting 记录在 await start 之前已有 child；适配器 stop 不等待 getState 请求（后者可能到官方 30 秒期限才结束）。任务 04 可直接在管理器内部遍历记录获得这些资源。
4. 当前 spawn 在 await start / await prompt 后还没有关闭状态判断；shutdown 插入后必须在这些边界防止继续订阅、提交或重新进入 ready。尤其是批量清空 Map 后的启动确认/初始 prompt 迟到完成。
5. 当前同步转发允许初始 prompt 尚未确认时的 settled；不要改成仅 ready 才收事件，否则会遗漏快速事件。应以运行时是否有效、记录身份、是否关闭来保护回报。
6. 文本读取完成后以及父投递前都要防止旧运行时回报；现有 listener 的 Map 身份判断只在回调入口有效，不能覆盖 await 期间发生的关闭/替换。
7. 当前 rollback 尝试一次 unsubscribe 和 stop；生产适配器 stop 已幂等。任务 04 添加批量清理后，应继续保留身份比较，不让旧失败操作删除替换记录。
8. `onEvent` 暂为明确的同步消费契约，不等待其返回值，也没有在这里偷偷吞掉异步 rejection；任务 04 必须在事件回报实现中显式捕获错误，不能直接塞入无人处理的 async listener。
