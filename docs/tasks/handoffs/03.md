## 最小线协议

UTF-8 JSON Lines，每帧一个 JSON 对象，以 LF 结尾。无握手/订阅/取消确认。上限 **1 MiB UTF-8 字节/帧（不含末尾 LF）**，包括未结束的部分帧；支持任意字节分片（包括 UTF-8 字符中间）、多帧同包。无效 JSON、无效 UTF-8、空行、非法结构/方向、超长帧均断开连接，并清理该连接的请求。忽略额外对象字段，不做协议版本协商。

```json
{"type":"request","id":1,"method":"inspect","params":{"wait":true}}
{"type":"response","id":1,"ok":true,"result":{"state":"idle"}}
{"type":"response","id":2,"ok":false,"error":{"code":"HANDLER_ERROR","message":"..."}}
{"type":"cancel","id":3}
```

- `params/result` 是 JSON 值；业务参数、结果形状和方法分派留任务 04。示例不是已实现的 inspect 业务 API。
- 编号为当前连接内正的安全整数，客户端从 1 单调增加；服务端要求 request 编号严格递增（允许跳号），重复/倒退则断开。不重用、不持久化，不是业务 ID。用尽后须重连。
- cancel 不占新编号；引用原请求。重复/未知/已完成的 cancel 无操作。取消没有 acknowledgement，也没有单独取消响应。
- 父侧忽略已结束编号的迟到响应（可能已在网络中），收到从未分配的未来编号或错误方向则作为协议错误断线。
- 处理器可即时返回，也可返回 Promise 延迟响应。每个请求独立登记，不串行 await；长 inspect 不阻塞状态查询。没有应用级发送队列；socket writable buffer 达到 2 MiB 上限时拒绝继续积压并断开慢连接。单次结果不适合无限增长，后续桥/工具须在此上限内处理结果，而不是增加持久化回复队列。

## 客户端 / 服务端 API

```typescript
import { SocketClient, SocketServer, SocketTransportError } from "./src/socket-transport.ts";

// 子侧；runDir 必须为任务 02 返回的原样绝对词法路径。
const server = await SocketServer.listen(runDir, (method, params, { id, signal }) => {
  // 返回 JsonValue 或 Promise<JsonValue>；这里再由任务 04 分派业务方法。
  // 延迟请求须同步监听 signal.abort 并释放自己的等待记录。
  return null;
});

// 父侧，可以复用一条连接并发请求。
const client = await SocketClient.connect(runDir);
const result = await client.request("inspect", { wait: true }, {
  signal,
  timeoutMs: 1800_000,
});
await client.close();
await server.close();
```

导出：`JsonValue`、`RequestOptions`、`TransportOptions`、`RequestContext`、`RequestHandler`、`SocketTransportError`、`SocketClient`、`SocketServer`。protocol 文件另导出帧类型、`FrameDecoder`、`parseFrame`、`encodeFrame`、`MAX_FRAME_BYTES`。

- `listen/connect` 的 `TransportOptions.address` 原样传给 `prepareSocketAddress`，用于测试注入；生产通常省略，父子环境必须一致。`connectTimeoutMs` 默认 5000，覆盖建立连接及服务端残留探活，不是等待业务的超时。
- `SocketClient.connect` 额外支持 `signal`。预取消直接拒绝；连接成功后此 signal 不再管理连接。
- `request(method, params = null, {timeoutMs = 30_000, signal} = {})` 返回 `Promise<JsonValue>`。**单位毫秒**，与工具秒数不同；任务 04/06 对长 inspect 必须显式传对应时长（规格默认 1800 秒），不要误用传输默认 30 秒。所有超时须为正的 32 位整数毫秒，非法配置抛 RangeError。单次超时包括本地发送至收到响应的全程，不是服务端执行时间保证。
- `socketPath` 只读；`client.pendingCount`、`server.pendingCount/connectionCount` 为只读内存诊断计数，不是工作状态、订阅或持久化信息。
- `close()` 幂等返回 Promise；服务端也允许处理器取消清理中重入 close。关闭会拒绝等待，不当作成功结果。
- `SocketTransportError.code`：本地 `ABORTED/TIMEOUT/CONNECTION_CLOSED/PROTOCOL_ERROR/FRAME_TOO_LARGE/BACKPRESSURE/ID_EXHAUSTED` 等；处理器抛该类时保留 code/message，否则用 `HANDLER_ERROR`。不可序列化/过大的处理器结果转换为该请求的 `RESPONSE_ERROR`；连接可继续使用。原生连接/I/O 错误保留 Node code，如 ENOENT/ECONNREFUSED；业务错误码由后续桥决定，不以 availability 类型代替协议错误。

## 取消语义与资源所有权（任务 04 必须遵守）

1. 父侧每请求拥有 pending、timeout timer、用户 signal 的监听器。响应、错误、取消、超时、断线、close 均通过一次性完成逻辑删除 pending、清 timer、解绑 signal。预取消不发 request。
2. 父侧取消/超时立即以 ABORTED/TIMEOUT 结束本地请求，并在原连接发送 `cancel(id)`；发送失败则关闭连接，依靠断线清理。不等待取消确认；网络延迟意味着父 Promise 拒绝时子侧可能尚未收到取消，但收到后同步移除 pending 并 abort 对应 signal。
3. 服务端每个连接独占自己的 pending Map 与 AbortController。cancel 先删除 pending，再 abort signal；断线/半关闭/无效帧/服务端 close 清空该连接 pending 并 abort，绝不影响其他连接。后续处理器 Promise 的完成/拒绝被消费，但不再生成响应。正常完成先删除 pending，再发送唯一响应，因此取消与完成按先到的一方结束。
4. **处理器/后续控制桥拥有业务等待记录及其业务事件监听器。** 它必须在 signal.abort 同步移除这些记录，正常完成/抛错时也要自行释放；可采用 once abort 监听 + 统一 cleanup。传输层不会强制终止任意 Promise，也不会等待不合作的 Promise 才允许关闭。不要在 abort 清理里等待 agent_settled，不要调用子 Pi abort、清空 steer/follow-up 或改变工作状态。
5. 正常完成不人为触发 signal.abort；不要将 abort 事件当作请求完成的通用 finally。延迟处理器须在 resolve/reject 前做正常清理；被取消后不要保留信号/请求上下文。通用 JS Promise 无法强制取消，外部未释放的处理器资源属于处理器责任。
6. 客户端拥有连接，close 不停止子代理、不删除 socket。服务端拥有监听器和接受的连接；close 先取消等待/销毁连接，再等 Node `server.close` 完成并自动 unlink 自己绑定的 Unix socket。没有手工重复 unlink，不删除 runtimeDir/runDir/session 文件；listen 失败不清理别人的端点。传输层不负责重新连接、Pi shutdown 或进程停止。

## 残留 socket 安全规则

`prepareSocketAddress` 先验证/准备私有 runtimeDir（沿用 02）。存在端点时要求是当前 UID 的真实 socket，普通文件、符号链接或非本用户 socket 直接报错，不删除。能连接就返回 `SOCKET_IN_USE`，不能覆盖，不需要协议握手来认定“有服务监听”。

仅 ECONNREFUSED 允许按残留处理；ENOENT 视作已消失，权限错误、连接超时或其他错误原样失败。删除前再次核对 dev/ino、再探活并核对 inode，观察到替换则拒绝。两个启动者最终仍由系统 bind 决定胜者，不以 socket 存在判断在线状态。

安全边界与 02 一致：私有目录不是对抗同 UID 恶意进程的事务沙箱，stat/probe/unlink 之间没有系统级原子比较删除；不宣称抵御恶意同 UID 的路径替换。监听期间端点不得由其他管理器主动 unlink/rebind；正常退出由监听者 Node 负责清理。没有实现 PID/锁文件/额外 metadata。
