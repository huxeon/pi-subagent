## 固定的名称、目录与路径规则

这些是 spec 授权实现时确定的具体规则，不添加另一套身份。

1. 名称按原 Unicode 字符串精确比较：**不 trim、不大小写折叠、不 NFC/NFD 归一化**。拒绝空白名称、C0/C1 控制字符、不能无损 UTF-8 往返的孤立 surrogate，以及超过 **126 UTF-8 字节**的名称。前后空格保留（仅全空白被拒绝）。
2. 子目录组件为 `n-` + 名称 UTF-8 字节的**小写 hex**。例如 `a -> n-61`。中文、emoji、斜线、反斜线、百分号、shell 特殊字符、`.`/`..` 均可作为名称，编码后不含路径分隔符，不产生穿越；`../x` 是字面名称而非相对路径。不同有效名称编码不碰撞，包括大小写及 Unicode 组合形式。126 字节映射为最长 254 字节的 ASCII 目录组件，适配本机 Linux 255 字节组件限制；不会截断名称或另造 ID。
3. `decodeName` 只接受可重新编码为**完全相同组件**的名称（含格式、大小写、UTF-8 有效性和长度校验）；其他组件返回 undefined。扫描不猜测旧实现目录。
4. 父会话组件为 `p-` + **Pi 现有 session ID** 的同一 UTF-8 hex 编码。调用者使用 `ctx.sessionManager.getSessionId()`，不使用可变 session label、session 文件 basename 或生成的新 ID。Pi UUID 在长度限制内；其他输入同样校验。
5. 持久化路径固定为 `<agentDir>/subagents/p-<hex-session-id>/n-<hex-name>/session.jsonl`。路径对象包含 `agentDir/subagentsDir/parentDir/name/runDir/sessionFile`；不同父会话隔离，同父会话创建由独占 mkdir 保证不覆盖。
6. `normalizeAbsolutePath(path, base?)` 使用 Node `resolve` 做**词法规范化**：折叠重复 `/`、`.`、`..` 和末尾 `/`；拒绝空路径/NUL；相对路径必须显式传绝对 base。此函数**不 realpath、不展开 ~ 或 $VAR**，也不写文件。Pi 的 agent-dir 展开交给宿主。`base` 对创建配置的 cwd 如何继承仍留 05。
7. **不合并符号链接别名**：agent-dir 可以是用户配置的符号链接，但应在 session_start 解析一次并固定同一规范化路径。父进程必须将返回的 `runDir` 原样作为绝对 `PI_SUBAGENT_RUN_DIR` 传给子进程；双方不能各自 realpath 或换用别名。直接使用另一词法路径会产生另一 socket 地址，不能把 inode 相同解释为地址相同。扩展管理的 subagents/parent/run 目录不允许 symlink；不提供迁移/删除别名目录能力。

### 创建与扫描调用

```typescript
const agentDir = resolveAgentDir(); // 在 session_start 固定
const paths = getSubagentPaths(agentDir, parentSessionId, name); // 纯计算
const reserved = await createSubagentDirectory(agentDir, parentSessionId, name);
const children = await scanSubagents(agentDir, parentSessionId);
```

- agentDir 必须由 Pi 已配置存在；创建 helper 仅逐层创建 subagents/parent（新目录 mode 0700），校验其为真实目录，再独占创建 runDir。EEXIST 原样报告，不把任何已有 runDir 视为可覆盖；失败不自动删除任何东西。失败清理由 05 在明确拥有目录后实现。
- helper 不预写空 JSONL。任务 01 已确认 setup-only 不落盘；**目录存在仍代表关系**，不要求 session 文件已存在才能被扫描发现。
- 扫描仅当前父会话目录的直接子项，canonical `n-` 名称 + 真实目录。排除普通文件、子目录 symlink、session.jsonl symlink/非普通文件；允许 session 缺失或普通文件。按编码后的绝对路径确定性排序。不递归查找，不读取/解析 JSONL，不将文件存在当作可恢复或在线的证据。
- subagents/parent 缺失返回空列表；受管祖先是文件/symlink 或 I/O 错误则抛错。不 chmod、不创建、不删除任何扫描数据。JSONL 有效性及 create 可恢复性检查必须由 05 独立实现。
- 没有抵御同 UID 进程并发替换目录的沙箱/事务保证；后续 destroy 不能仅凭扫描结果盲目递归删除，须在操作时重新校验归属及路径。

## 固定的 socket 地址规则（供 03 使用）

```typescript
const { runtimeDir, socketPath } = await prepareSocketAddress(paths.runDir);
// 03 才在 socketPath 监听/连接。
```

- `hashRunDirectory` 对规范化后的**绝对词法路径 UTF-8 字节**计算 SHA-256，取前 32 个小写十六进制字符。父子同用这一实现；它只是路径编码，不是业务 ID。
- 优先有效 XDG_RUNTIME_DIR：必须绝对、存在、真实目录、当前 UID 所有、权限（含特殊位）恰为 0700，且 realpath 与规范化路径相等（不经过 symlink）。不修复或创建 XDG 本身。空/相对/缺失/不可访问/类型或所有权或权限不合格则回退。
- 有效 XDG 下使用 `<XDG>/pi-subagent/<hash>.sock`，否则使用 `/tmp/pi-subagent-<uid>/<hash>.sock`。默认回退不读 TMPDIR。检查临时根为 root 或当前 UID 所有的真实非链接目录；若组/其他用户可写则必须有 sticky bit（兼容 /tmp）。
- 只创建最终的专用 runtimeDir，mode 0700；已有目录必须当前 UID 所有、恰好 0700、没有 symlink。**已有不安全专用目录直接报错，不 chmod/chown/unlink，也不偷偷再换地址。** 父/子应避免在运行期间变更用于计算的 XDG 环境。
- 完整 socket 路径按 **UTF-8 字节数**检查，Linux 默认 <=107，其他平台采用保守 <=103。超长报错；有效但超长 XDG 不改选 fallback。校验先于专用目录创建。不创建 socket 文件。
- `socketPathFor` 可纯计算给定 runtimeDir 的地址，但**不验证目录安全**。需要实际使用时走 `prepareSocketAddress`。`uid/tmpRoot/maxBytes/xdgRuntimeDir` 是可注入选项用于边界测试，生产一般不传。
- 不实现 stale socket 清理、探活、身份握手、超时、协议请求 ID；不能依据文件存在判断活着。
