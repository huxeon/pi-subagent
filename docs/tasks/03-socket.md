# 03 — Unix socket 请求、响应和取消

## 依赖与阅读

- 依赖 02，阅读前序交接。
- spec：第 7 节、4.3 的取消与超时、第 5 节。

## 目标

实现可测试的本地请求/响应传输层，尚不依赖 Pi。子代理为服务端，父代理为客户端。

## 工作

1. 定义小型协议：请求编号、方法、参数、成功/错误响应、取消请求；请求编号仅用于通信，不是业务 ID。
2. 实现分帧（可使用 JSON Lines），处理分片、多帧、无效帧和合理的帧大小上限。不引入通用 RPC 框架。
3. 支持即时响应和延迟响应，后者供 inspect(wait=true) 使用。
4. 客户端支持超时与 AbortSignal；取消需通知服务端，服务端清理相应请求。
5. 断线清理该连接的未完成请求；完成/取消竞态不得重复响应，不留监听器、定时器或 pending 记录。
6. 实现监听、连接与关闭，以及残留 socket 的安全检查：已能连接的 socket 不能直接删除。
7. 允许 UI 短状态查询与长 inspect 等待并存，不让一次长等待阻塞其他请求。

## 验收

使用临时目录和假处理器测试：即时/延迟响应、并发、分片、错误、取消、超时、断开、重复完成、关闭清理、有效 socket 不被覆盖。默认不启动 Pi 或 tmux。

交接写清协议、客户端/服务端 API、取消责任和资源所有权。不得顺带增加状态订阅、持久化队列或工作版本号。
