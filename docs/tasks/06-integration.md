## 实现范围

1. 补齐从扩展工具入口到管理器、RPC 适配器、事件回报及 shutdown 的集成测试。
2. 使用受控 fixture 或本地假 provider 验证官方 RpcClient 与真实 CLI 链路；模型输出必须由本地固定响应产生，不调用真实模型。
3. 测试夹具放在临时目录中，隔离配置、认证和资源，结束后清理。
4. 单独验证生产工具注册的排除效果：传入规格要求的 exclude 参数后，子代理不能使用本扩展的 spawn/send；不能用 --no-extensions 或测试中根本没加载本扩展来证明排除有效。
5. 更新 README：安装/加载、工具参数、异步回报、模型继承规则、生命周期、测试命令及已验证范围。
6. 如有实现偏离规格，修正实现；产品级变更先取得用户确认，不通过删改规格掩盖失败。

## 必须覆盖的链路

- spawn → 接收确认返回 → 子代理工作 → settled → subagent.report。
- 子代理完成后不退出，继续 send 并再次回报。
- 运行中 steer/followUp 的传参及实际接收；不要求逐条 send 都有独立回报。
- 两个不同名字并行运行，回报归属正确；同名创建被拒绝。
- thinking 单独覆盖；provider/model 成组覆盖或继承。
- 压缩中提交被拒绝，工具直接返回错误，无扩展层重试。
- 父 shutdown 覆盖正常空闲、仍在工作和仍在启动的子代理，无迟到回报或进程遗留。
- 正确使用 `subagent.report`、steer 和 triggerTurn。
- 子代理实际加载本扩展后，排除参数仍能阻止嵌套调用。

可以分层验证：SDK 替身负责精确竞态和错误路径，受控真实 CLI 负责协议、启动及排除集成。不要把仅验证参数的单元测试描述为已验证模型调度。
