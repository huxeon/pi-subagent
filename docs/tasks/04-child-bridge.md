# 04 — 子代理控制桥

## 依赖与阅读

- 依赖 03，阅读前序交接和 implementation-notes。
- spec：3.2/3.3、4.2/4.3、第 5、7 节及相关时序图。
- 当前 Pi 扩展生命周期/API 文档和实际类型，按开发环境规则阅读。

## 目标

把 socket 服务端接到子 Pi，提供消息、状态和等待能力。不实现父侧 tmux 管理、工具卡片或 UI。

## 工作

1. 从专用环境变量识别子代理角色；在 session_start 启动控制桥，不在扩展工厂直接启动长期资源。
2. 子代理不注册 subagent 工具；正常资源发现不做额外筛选。遵循 01 确认的加载方式，避免重复桥。
3. 状态仅 working/idle，在内存中通过 Pi 事件和 isIdle 维护；agent_end 不是最终完成信号。
4. message：空闲直接 sendUserMessage；忙碌按 followUp 选择 steer/followUp；调用成功即确认。不增加投递中状态、版本号或自己的队列。
5. inspect 不等待仅返回状态；等待时 idle 立即返回状态和最新回复，working 登记延迟请求，agent_settled 后响应。
6. 最新回复按 Pi 当前会话/分支获取，保留错误或中止信息，不把旧分支回复当结果。
7. 超时、取消和断线移除等待请求，不中断 Pi；桥关闭清理 socket 和所有等待。重载/切换的细节遵循已验证生命周期。

## 验收

- 以 Pi 适配器或事件桩测试 idle/working、两种忙碌投递、等待完成、取消后不再响应、断线清理。
- 非等待 inspect 不读取或返回最新回复。
- 多个等待请求互不干扰，取消不会调用 abort 或修改 Pi 队列。
- 子角色不存在 subagent 工具注册。
- typecheck、相关测试通过；实际宿主加载若未验证需明确记录。
