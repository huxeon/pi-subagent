# 03：命名子代理管理

## 目标

实现只等待接收确认的 spawn/send，以及名字、配置和启动资源的管理。

## 前置与阅读

- 任务 01–02 已完成。
- 阅读规格、任务索引、前置交接，以及配置解析和 RPC 适配代码、测试。
- 核对 Pi prompt 接收状态与并发提交行为的相关文档和类型。

## 实现范围

建议新增 `src/manager.ts`，复用已有配置解析和 RPC 适配器。

1. 每个父运行时持有独立管理器，按名字维护子代理和启动中的预留记录。
2. spawn 在任何异步启动前校验并预留名字，阻止并发重名；不覆盖或复用既有记录。
3. 使用调用时的父配置快照和 cwd，创建子代理并在提交消息前订阅事件。
4. 收到 prompt 接收确认后立即返回名字及 disposition，不等待 settled。
5. send 按名字查找子代理，默认 steer，通过统一 prompt 入口提交并返回接收状态。
6. 名字不存在或提交失败时返回错误；压缩错误不重试。
7. 启动或初始消息失败时，取消订阅、停止本次客户端并释放名字；回滚不得误删其他记录。
8. 为任务 04 提供最小事件转发和资源访问边界，使管理器在 spawn 返回前就能接收快速事件。不要在此任务模拟父消息投递或留下丢弃事件的临时占位实现。

如何处理启动中的同名 send，应采用明确的失败行为并测试，不能隐式排队引入新的发送队列。

## 必须测试

使用受控 fake client 和可手动完成的 Promise，不调用模型：

- spawn 等待接收确认，但不等待 settled；handled 也能正常返回。
- 并发同名 spawn 仅创建一个客户端，失败方不影响成功方。
- 不同名字可并行创建。
- provider/model 配对、thinking 独立继承和父配置快照实际传递正确。
- 初始 prompt 前已订阅事件，不遗漏快速完成事件。
- start 或初始 prompt 失败后清理资源并释放名字，可重新创建。
- 未知名字、默认 steer、显式 followUp、各 disposition 及压缩错误。
- send 不调用单独的 steer/followUp，不等待任务结束。

## 验收与交接

- 类型检查和全部默认测试通过。
- spawn/send 只有当前规格内的行为，没有 list/status/wait/stop 模型工具。
- 写入 `docs/tasks/handoffs/03.md`，记录管理器接口、记录生命周期、事件边界和任务 04 需要覆盖的关闭竞态。

## 不做

不注册模型工具、不投递父 custom message；运行时级批量 shutdown 与关闭竞态由任务 04 完成。
