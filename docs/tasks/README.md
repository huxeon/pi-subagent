# 分会话实现计划

## 使用方式

每个任务使用一个新会话，按下表顺序执行。`docs/spec.md` 是产品行为的唯一依据，本目录只是实施拆分，不替代或扩展规格。

每次会话只需先读本文件、对应任务文档、已有交接记录以及任务列出的 spec 章节。不要求每次完整重读 spec；涉及跨模块行为时再补读。Pi 文档的阅读规则仍按开发环境指示执行。

任务文档给出的模块名只是建议。实现者应优先复用已经建立的结构，不另起平行实现。

## 通用约束

- 不新增 metadata.json、持久化 inbox、任务版本号、独立消息调度器或业务 ID。
- 不擅自改变规格。如果 Pi 实际行为使规格不可实现，记录证据并暂停相关部分，向用户确认，不静默绕过。
- 正常加载的其他扩展和技能不做筛选；子代理只是不注册本扩展的 subagent 工具。
- 测试不依赖真实模型调用作为默认步骤；必要的真实测试须说明资源、权限和清理范围。
- 不执行会关闭用户已有 tmux session、删除已有会话记录或中止现有 Pi 的测试。
- 每步增加本步相关测试，不把全部测试推迟到最后。
- 不默认提交 Git；按用户要求处理提交。

## 每个任务结束时的交接

创建或更新 `docs/tasks/handoffs/NN.md`，至少记录：

1. 已完成和未完成的工作、关键文件路径。
2. 导出的接口、事件语义、下一任务需要知道的调用方法。
3. 采用的具体规则（路径编码、协议、配置恢复等）和依据，避免下一会话重复猜测。
4. 执行的测试/命令及结果，明确区分自动测试、手动验证、未验证项。
5. 是否有阻塞、用户已确认的变更，以及下一任务的注意事项。

同时更新本表状态。不要把计划中的功能记成已经实现。

## 新会话通用提示

复制下列文本，替换任务编号：

> 请执行 docs/tasks/NN-xxx.md 中的任务。先阅读 docs/tasks/README.md、该任务文档及其依赖任务的交接记录，再按文档指定范围阅读 docs/spec.md 和现有代码。遵守项目及 Pi 开发文档阅读要求。仅实现本任务范围，不提前实现后续任务。遇到规格与实际 API 冲突先报告。完成后运行相关检查，写交接记录并更新任务状态。
