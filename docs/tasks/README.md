## 所有任务的共同要求

- 实现前阅读相关 Pi 文档和示例；路径基于 `node_modules/@earendil-works/pi-coding-agent/`，不是本项目的 `docs/`。
- 使用官方 `RpcClient`，不重新实现 JSONL 协议，不修改 Pi 或 node_modules。
- 不添加持久化、socket、tmux、worktree、恢复、自动重试、异常退出通知、额外管理工具或 TUI 功能。
- 默认测试不调用真实模型，不消费用户 API 配额，不操作用户现有会话或配置。
- 配置、RPC 客户端创建和结果投递使用最小的可注入边界，便于受控测试；不为测试构造通用框架。
- 每个任务随实现补齐自己的测试，不将全部测试推迟到任务 06。
- 每个任务结束前运行 `npm run typecheck`、当前全部默认测试和 `git diff --check`。任务 01 负责建立默认测试命令。
- 新增依赖时同步锁文件，避免把 Pi 提供的宿主包重复作为运行时依赖安装。
- 只有通过测试的真实行为才能记为已验证；未执行、跳过或需要人工确认的内容单独列出。

## 工具接口与排除约定

`subagent` 提供 `spawn`、`send` 两个子命令，以 `action: "spawn" | "send"` 选择。子进程使用 `--exclude-tools subagent` 排除整个工具；具体参数及行为以 `docs/spec.md` 为准。

任务 01 验证排除后的模型声明、工具注册和实际可执行性，包括其他工具通过嵌套调用访问两个子命令的路径。后续任务沿用该接口，并对生产注册补齐集成验证。

## 交接记录

每个任务结束时创建 `docs/tasks/handoffs/NN.md`，内容包括：

1. 完成范围及涉及文件。
2. 实际接口、关键约束和可复用的测试设施。
3. 已执行的命令及结果。
4. 未验证项、阻塞问题和后续注意事项。
5. 下一任务需要阅读的文件。

交接记录以实际代码为准；任务文件中的模块路径只是建议，可按职责调整，并在交接中说明。不要为满足预期路径留下空实现或未接线的占位逻辑。
