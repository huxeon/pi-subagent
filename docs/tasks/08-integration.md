# 08 — 端到端验收与使用文档

## 依赖与阅读

- 依赖 07，阅读全部交接和 implementation-notes。
- 本任务完整阅读 spec，逐项核对最终实现，避免只测试 happy path。

## 目标

补齐跨模块集成测试、真实环境验收和使用说明，确认功能与规格一致，而不是新增能力。

## 工作

1. 用受控假 Pi/测试启动器串起 create → working → message → inspect → idle → destroy，不让默认测试调用真实模型。
2. 覆盖 follow-up、等待取消/超时后继续工作、不再回复已取消请求、连接丢失及子代理意外退出。
3. 覆盖父 reload 不停止子代理；父退出/切换停止但保留 session；恢复仅加载历史并空闲；destroy 删除记录。
4. 验证启动早期停止与恢复、不同父会话同名隔离、子代理不注册工具、资源发现不受额外过滤。
5. 检查 socket 残留、进程泄漏、定时器泄漏、恢复重复启动及失败清理边界。
6. 核对四种工具卡片、widget、选择界面与 spec 示例一致，检查非 TUI 行为。
7. 更新 README：环境要求、安装/加载、工具参数、人工入口、生命周期、destroy 不保留历史、已知限制、开发测试命令。删除“只有骨架/入口不可加载”等过时描述。
8. 将仍未验证的真实 Pi/模型行为单列，不以模拟测试代替真实结论；需要付费调用或破坏性环境操作先征得用户同意。

## 验收

- typecheck、所有单元/集成测试通过，测试结束不留进程、socket 和测试数据。
- 有逐项手动验收记录，明确通过、失败、受环境限制的项。
- spec 与实现无未说明偏差；需改产品行为时先向用户确认。
- 新会话只看 README 即能理解如何加载和使用扩展。
- 写最终交接，列出功能完成度、剩余问题和后续建议，不扩大本次范围。
