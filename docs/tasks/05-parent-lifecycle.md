# 05 — 父侧管理与生命周期

## 依赖与阅读

- 依赖 04，阅读前序交接和 implementation-notes。
- spec：第 3、6、7、8 节，4.1/4.4 及第 12 节。
- 参考 shared.ts 的启动、index.ts 的父侧恢复与退出，仅借鉴已确认行为。

## 目标

提供不依赖渲染的协作者管理服务，贯通创建、连接、暂停、恢复和销毁。后续工具与 UI 共用它。

## 工作

1. 创建：检查当前父会话内名称唯一性，解析配置继承，创建目录并启动独立 tmux session。
2. 启动时可靠传入子角色、会话路径和配置；恢复方式使用 01 验证结论，不依赖 metadata。
3. 等待控制桥和会话恢复条件就绪，提交初始 prompt；返回成功不等任务完成。创建失败处理自己已创建的资源，不碰已有协作者。
4. 实现 message、即时 inspect、等待 inspect 的父侧封装，向上传递超时和取消。
5. destroy：终止对应进程，等待结束，清理残留 socket 和整个目录；对已停止的协作者也有效。
6. session_start 扫描目录：能连接则重连，否则检查存活进程和残留 socket 后恢复，避免重复启动。单个失败不应阻止其他协作者恢复。
7. 父侧 session_shutdown：reload 不停子；正常退出/切换停止子但留历史。清理幂等，不保存 suspended 标志。
8. 进程管理与 Pi 上下文解耦，便于假进程测试；不得依赖 shell 拼接不可信名称/路径。

## 验收

- 桩测试覆盖同名、继承配置、启动失败、就绪超时、重复清理、恢复、reload 与退出区别、destroy。
- 在可用环境中用受控测试进程验证 tmux 启停和重连，不发起默认真实模型调用，不操作用户已有 session。
- 无 metadata、inbox、状态文件或自动重放旧任务。
- 交接说明管理服务 API、资源清理和仍未真实验证的路径。
