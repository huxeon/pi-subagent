# 07 — 状态 widget 与选择进入

## 依赖与阅读

- 依赖 06，阅读管理服务、传输和生命周期交接。
- spec：第 9、8 节，7.2。
- 当前 Pi 的 extensions、tui、keybindings 等相关文档和选择列表/终端接管示例；完整遵循开发环境的文档阅读要求。
- 参考 index.ts 中的 widget 与 /subagent，仅借鉴已确认行为。

## 目标

在父 Pi 交互式 TUI 提供每秒刷新的常驻 widget 和 /subagent 选择入口，不增加状态订阅协议。

## 工作

1. 建立单一 UI 状态刷新器，widget 与已打开列表共用快照，每秒本地 socket 查询。
2. 查询设短超时，不叠加刷新，单条失败不阻塞其他条目；UI 缓存不代替工具 inspect 的直接查询。
3. 编辑器下方紧凑显示名称/状态，无协作者时隐藏；多条目控制宽度，使用主题语义颜色。
4. /subagent 列表支持键盘选择、确认、取消；刷新不丢失当前选择。不以鼠标为必要条件。
5. 父 Pi 在 tmux 内 switch-client；不在 tmux 内暂停父 TUI 后 attach，detach/失败后正确恢复。不可用条目不能误进入。
6. 非 TUI 不启动界面、轮询或终端接管；子角色不注册父侧人工入口。
7. session_shutdown、reload、会话切换清理定时器、UI 连接、旧上下文和 widget；不得停止应跨 reload 存活的子代理。

## 验收

- 假时钟/连接测试：单刷新器、超时、不重入、列表稳定、生命周期清理、非 TUI 无轮询。
- 人工验证窄终端、中文长名称、零/多协作者、状态变化、不可用条目。
- 在 tmux 内外分别手动验证进入与返回（环境不支持的项明确标记未验证）。
- 不改变工具 inspect 等待语义，不新增状态持久化或订阅协议。
